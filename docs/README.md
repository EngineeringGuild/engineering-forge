## 🎯 **Visão Geral**

Este é o **ponto de entrada principal** para toda a documentação do projeto **Engineering Forge**. A estrutura foi organizada seguindo **Domain-Driven Design (DDD)** e os melhores padrões do mercado para facilitar o desenvolvimento, manutenção e evolução do projeto.

### **🏗️ Arquitetura da Documentação**

A documentação está organizada em **domínios de negócio** claramente definidos, permitindo:
- **Desenvolvimento modular** e escalável
- **Controle granular** de tarefas e progresso
- **Facilidade para AI** seguir e implementar
- **Sincronização** entre todas as versões do produto
- **Padrões profissionais** do mercado

## 🏢 **Domínios de Negócio (DDD)**

### **📚 [Educação](DOMAINS/education/README.md)**
Sistema educacional completo com cursos, lições, projetos e certificações.
- **Entidades**: Curso, Lição, Projeto, Avaliação
- **Serviços**: Currículo, Progresso, Certificação
- **Casos de Uso**: Matricular, Completar, Avaliar

Mecânicas de jogo, física, componentes e sistema de conquistas.
- **Entidades**: Sessão, Componente, Projeto, Conquista
- **Serviços**: Física, Montagem, Conquistas
- **Casos de Uso**: Construir, Testar, Desbloquear

- **Entidades**: NFT, Carteira, Transação, Certificado
- **Serviços**: Minting, Trading, Validação

Sistema de compra, venda e troca de componentes e NFTs.

## 🤖 **Sistema Cursor (OBRIGATÓRIO)**

### **⚠️ ATENÇÃO: Sistema Cursor Ativo**
O projeto Engineering Forge possui um **sistema Cursor obrigatório** que deve ser seguido em todas as interações.

### **📚 Documentos do Sistema Cursor**
- **🚨 [CURSOR-SYSTEM.md](CURSOR-SYSTEM.md)** - Sistema principal (LER PRIMEIRO)
- **🚨 [CURSOR-RULES.md](CURSOR-RULES.md)** - Regras obrigatórias
- **🤖 [CURSOR-METHODOLOGY.md](CURSOR-METHODOLOGY.md)** - Metodologia de trabalho
- **📋 [CURSOR-COMMANDS.md](CURSOR-COMMANDS.md)** - Comandos padronizados
- **📝 [CURSOR-CHAT-TEMPLATE.md](CURSOR-CHAT-TEMPLATE.md)** - Template de chat

### **🚨 REGRAS OBRIGATÓRIAS**
1. **SEMPRE** ler `CURSOR-SYSTEM.md` primeiro
2. **SEMPRE** usar o template de chat obrigatório
3. **SEMPRE** seguir a metodologia estabelecida
4. **SEMPRE** usar comandos padronizados
5. **SEMPRE** manter sincronização

### **Comandos Principais**
```bash
# Inicialização (OBRIGATÓRIO)
@ai read-methodology                       # Ler metodologia
@ai check-status                          # Verificar status
@ai read-domain [domain]                  # Ler domínio
@ai read-version [version]                # Ler versão

# Tarefas
@ai create-task [domain] [description]     # Criar tarefa
@ai update-task [ID] [status]              # Atualizar tarefa
@ai list-tasks [filter]                    # Listar tarefas

# Implementação
@ai implement [domain] [feature]           # Implementar feature
@ai review-code [file]                     # Revisar código
@ai generate-tests [component]             # Gerar testes

# Sincronização (OBRIGATÓRIO)
@ai update-dashboard [task-id] [status]    # Atualizar dashboard
@ai sync-domain [domain]                   # Sincronizar domínio
@ai check-consistency [scope]              # Verificar consistência
@ai update-docs [section]                  # Atualizar documentação
```

### **Sistema de Versionamento**
- **v1.0**: Versão inicial
- **v1.1**: Pequenas correções
- **v2.0**: Mudanças significativas
- **v2.1**: Novas features
